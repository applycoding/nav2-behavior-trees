# Build tasks: nav2-behavior-trees

Do the tasks in order, on a feature branch, following PLAN.md exactly. Deviate only if a pin or a test proves a step broken. If you do, record the reason and the measured data in `DEVIATIONS.md`. **Never weaken a threshold, gate or mutant expectation to make CI green.** If a gate fails, fix the implementation.

Every commit's author and committer is **Arpan Bom <applycoding@gmail.com>**. Do not add `Co-authored-by` trailers. Commit messages and repo text carry no tool attribution and no "generated by" lines. The licence is **Apache-2.0**, and the project is simulation only.

A task is done only when its **Accept** checks pass.

## 3. NavBackend and GridSim

- Write `nav_backend.hpp` (PLAN §4).
- Implement `GridSim` with the frozen map, A*, motion, real versus costmap occupancy, coverage, battery, timed actions, the tick order, overlap and collision counters, and the scenario event hooks (PLAN §6-§7).
- Write unit tests on a hand-built 5×5 grid. Expected masks and paths must be written by hand, not recomputed with production code. Cover these cases:
  - corner cutting is forbidden
  - BLOCKED fails without moving
  - a deliberate collision path increments `collisions` (test-only API)
  - `cancel` is idempotent
  - a second `send` while a goal is RUNNING is refused and counted
  - battery clamp and failure at zero
  - charging happens only during `Charge`

**Accept:** the unit tests pass, and the zone free-cell counts are 240, 234 and 231 with lane counts 7, 7 and 5.
